# POTENTIAL INCOMPATIBILITIES

- An external DTD was automatically fetched by `xmerl_scan` which resulted in a
  scan of an untrusted DTD that may result in an out of memory crash.

  `xmerl_xcan` has now got a new option `{fetch_external_DTD, Boolean}` which
  default set to `false` to protect against this. This result in an
  incompatibility if one took advantage of that `xmerl_scan` auto fetched the
  external DTD.

  The secure way to use a DTD is to let `fetch_external_DTD` be `false`
  (default) and use doctype_DTD to provide the needed DTD in the call to
  `xmerl_scan`.

  Own Id: OTP-20556
  Application(s): xmerl
  Related Id(s): PR-12241, CVE-2026-119443

# crypto-5.10.1

The crypto-5.10.1 application can be applied independently of other applications
on a full OTP 29 installation.

## Fixed Bugs and Malfunctions

- Fixed two bugs in the AES-GCM decryption fallback used when crypto is built
  against OpenSSL 1.0.1 through 1.0.1c: the ciphertext and AAD arguments were
  swapped, and an empty authentication tag was not rejected. AES-GCM decryption
  on these builds now behaves the same as on all other OpenSSL versions.

  Own Id: OTP-20381
  Related Id(s): PR-11927

- Added bounds checks to crypto:pbkdf2_hmac/5. The password, salt, iteration
  count and derived key length must now be at most INT_MAX, otherwise a `badarg`
  exception is raised.

  Own Id: OTP-20514
  Related Id(s): PR-11938

- When crypto was built against OpenSSL 3.x,
  `crypto:generate_key(rsa, {ModulusSize, PublicExponent})` could generate a key
  with a different public exponent than requested on little-endian machines.

  Own Id: OTP-20515
  Related Id(s): PR-11939

- crypto:hash_final_xof/2 (SHAKE128/SHAKE256) now runs on a dirty CPU
  scheduler when the requested output is large. Before this fix, asking for a
  long XOF output could block a normal scheduler for a long time and hurt the
  responsiveness of other processes.

  Own Id: OTP-20551
  Related Id(s): PR-12200

> #### Full runtime dependencies of crypto-5.10.1
>
> erts-9.0, kernel-6.0, stdlib-3.9

## Fixed Bugs and Malfunctions

- Fix race between ets:delete/1 and exiting process auto unfixing the table.
  Could cause emulator crash.

  Own Id: OTP-20462
  Related Id(s): ERIERL-1338, PR-11908

  runtime instances; one node in a cluster could say `A < B` where another said
  `A >= B`.

  Own Id: OTP-20511
  Related Id(s): PR-11568

  crash.

  Only AArch64 (ARM64) systems running the JIT were affected. The x86-64 JIT,
  interpreter (emu) builds, and 32-bit platforms were not affected.

  Own Id: OTP-20523
  Related Id(s): PR-11967, CVE-2026-115747

  bitstrings has been fixed.

- A bug that reduced garbage collection efficiency has been fixed.

  Own Id: OTP-20528
  Related Id(s): GH-11923, PR-11971

  Could cause beam emulator crash instead of badarg exception.

  Own Id: OTP-20530
  Related Id(s): PR-12043, CVE-2026-116293

- Port commands with the `nosuspend` option could be executed by the port even
  though it had set itself in a busy state.

  Own Id: OTP-20534
  Related Id(s): GH-11941, PR-11942

- Fixed bug in `term_to_binary(Term,local)`. Caused emulator crash if `Term`
  contained funs.

  Own Id: OTP-20545
  Related Id(s): PR-12148

- The `ct_run` command no longer crashes with a segmentation fault when
  `-sname`, `-name`, `-browser` or `-ctname` is given as the last argument
  without a value. It now prints an error message and exits with status 1.

  Own Id: OTP-20546
  Related Id(s): PR-12147

  Own Id: OTP-20555
  Related Id(s): PR-12182, CVE-2026-117642

# inets-9.8.2

The inets-9.8.2 application can be applied independently of other applications
on a full OTP 29 installation.

## Fixed Bugs and Malfunctions

- Fixed a vulnerability in the inets HTTP server (httpd) where a request header
  name could create a new atom in the atom table. Since atoms are never
  reclaimed, an unauthenticated client able to reach an Erlang Server Interface
  (ESI) URL prefix could grow the atom table with ordinary HTTP requests until
  the runtime system aborted when the atom limit was reached, taking down all
  applications on the node. Only servers with at least one `erl_script_alias`
  configured are affected. Servers without ESI, CGI scripts served by `mod_cgi`,
  and the `httpc` client are unaffected. When building the environment passed to
  an ESI callback, `httpd` now derives the `{http_<header-name>, string()}` keys
  from a fixed set of standard request header names instead of constructing an
  atom from the header name received. The documented `mod_esi` contract is
  unchanged for those headers. A header outside that set is now reported under
  `http_other`, which is already where a header whose name is not an existing
  atom has always been placed.

  Own Id: OTP-20458
  Related Id(s): GH-SA-7fjc-wcvc-vp96, PR-12262, CVE-2026-116382

- CR, LF and NUL characters in HTTP header field names and values are now
  replaced with a space before the header is sent. This applies to request
  headers sent by httpc, including when the headers_as_is option is used, to
  response headers sent by httpd, and to chunked trailers.

  Previously, an application that placed untrusted data in an httpc request
  header could allow injection of additional header lines or of a second
  request.

  Own Id: OTP-20571
  Related Id(s): GH-SA-84cc-vh37-jqpf, PR-12263, CVE-2026-116295

- Fixed a memory leak in the process calling httpc:request/4,5. Every
  asynchronous request, and every request given an explicit receiver option,
  left an active process alias behind in the calling process, so a long-lived
  process making many such requests would grow without bound. An alias is now
  only created for synchronous requests, and it is always deactivated when the
  request completes or fails.

  Own Id: OTP-20580
  Related Id(s): GH-11829, PR-11687

> #### Full runtime dependencies of inets-9.8.2
>
> erts-14.0, kernel-9.0, mnesia-4.12, public_key-1.13, runtime_tools-1.8.14,
> ssl-9.0, stdlib-5.0, stdlib-6.0

# snmp-5.20.7

The snmp-5.20.7 application can be applied independently of other applications
on a full OTP 29 installation.

## Fixed Bugs and Malfunctions

- snmp_pdus now enforces the OBJECT IDENTIFIER limits given in RFC 2578, section
  3.5, when decoding: at most 128 sub-identifiers per OID, and a maximum
  sub-identifier value of 2^32-1, which requires at most five BER content
  octets. A single sub-identifier spread over a large number of continuation
  octets was previously accepted, and the decoding time grew quadratically with
  its length — decoding one sub-identifier of 64 kB took roughly 230 ms of CPU,
  and 500 kB took over 13 seconds. Since OIDs are also decoded for messages that
  have not been authenticated, a peer could use this to make an agent or manager
  unresponsive.

  Own Id: OTP-20429
  Related Id(s): GH-SA-9p2q-5p4x-rhpq, PR-12261, CVE-2026-116225

- The SNMP agent can once again complete engine-ID discovery that it initiates
  itself with `snmpa:discovery/2,3,4,5,6`. Since OTP 27.3.4.19, 28.5.0.8 and
  29.1.2 (OTP-20427), the agent silently discarded the manager's Report
  answering a stage-1 discovery request, because the Report carries the
  manager's engine ID, which is not yet known to the agent. Discovery therefore
  timed out, the engine ID of the target was never learned, and no INFORM was
  sent to managers whose engine ID is not configured.

  The agent now accepts such a Report, as allowed by RFC 3414, section 3.2, step
  3a, provided it answers a discovery request still pending from the agent. The
  behaviour introduced by OTP-20427 for incoming messages is unchanged.

  Own Id: OTP-20584
  Related Id(s): ERIERL-1362, ERIERL-1384, ERIERL-1385, PR-12274

> #### Full runtime dependencies of snmp-5.20.7
>
> asn1-5.4, crypto-4.6, erts-12.0, kernel-8.0, mnesia-4.12,
> runtime_tools-1.8.14, stdlib-5.0
